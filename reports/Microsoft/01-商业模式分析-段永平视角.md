## 2. 商业模式本质与收入结构

### 2.1 三个分部（FY26 口径，一手：FY2026 10-K Item 7 "Segment Results of Operations"）

| 分部 | FY26 营收 | FY26 经营利润 | 利润率 | FY25 利润率 | 营收增量 | 利润增量 | 增量利润率 | 生意本质 |
|---|---|---|---|---|---|---|---|---|
| Productivity & Business Processes（PBP） | 1,400.0 | 838.8 | **59.9%** | 57.8% | +191.9 | +141.1 | 73.5% | 按席位收租：M365 商业云（含 Copilot）、M365 消费、LinkedIn、Dynamics |
| Intelligent Cloud（IC） | 1,377.9 | 569.7 | **41.3%** | 42.0% | +315.3 | +123.8 | 39.3% | 按消耗计费的算力/平台：Azure、Server 产品、GitHub 云、企业服务 |
| More Personal Computing（MPC） | 540.5 | 143.9 | **26.6%** | 25.9% | −6.0 | +2.2 | — | Windows OEM、Xbox、搜索广告：存量与周期性 |
| 合计 | 3,318.4 | 1,552.4 | 46.8% | 45.6% | +501.2 | +267.1 | 53.3% | |

Q4 FY26 单季（一手：Q4 FY26 8-K Ex.99.1 分部表；与底稿 §4 一致）：PBP 378.5 / 219.0（57.9%）；IC 393.1 / 159.6（40.6%）；MPC 128.5 / 27.5（21.4%）。

**数据显示的三个事实：**
1. **存量利润靠 PBP**：PBP 以 42% 的收入贡献 54% 的经营利润，利润率 60%，且增量利润率 73.5%——这是典型的"收租"生意，边际成本极低。
2. **增量收入靠 IC，但 IC 增量利润率只有 39%**：IC 营收 +30%，但成本 +44%（10-K 原文："Cost of revenue increased $17.7 billion or 44% driven by investments in AI infrastructure"），毛利率下降。AI 带来的是"高增长、低边际利润率"的收入。
3. **MPC 是拖累**：营收下滑，Xbox 硬件 −29%、Xbox 内容与服务 −5%（10-K），Q4 计提 Xbox 减值（8-K Ex.99.1）。

### 2.2 Microsoft Cloud（非 GAAP 汇总口径）包含什么

一手（FY2026 10-K Item 7）：**"Microsoft 365 Commercial cloud, Azure and other cloud services, the commercial portion of LinkedIn, and Dynamics 365"**；FY26 = **2,144 亿（+27%）**，占总收入 64.6%；FY25 1,689 亿、FY24 1,377 亿。
- 注意：它跨越 PBP 与 IC 两个分部，不含 M365 消费云、Windows、Xbox、搜索。
- **FY27 起定义变更**（一手：2026-09-02 8-K Ex.99.1）："revenue from Azure, Microsoft 365 commercial cloud, and Industry solutions cloud"——LinkedIn 商业部分并入 Industry solutions cloud 与 Search and advertising，Microsoft Cloud 口径与旧口径不再完全可比。

### 2.3 FY27 起的新看法：两个分部 + 重述后的产品线（一手：2026-09-02 8-K Ex.99.1）

| FY27 新分部 | FY26 重述营收 | FY26 重述经营利润 | 利润率 |
|---|---|---|---|
| Agents and Infra（= Microsoft Cloud + 生产力/服务器许可 + 咨询支持） | 2,681.3 | 1,363.7 | 50.9% |
| Devices and Consumer（Windows、Xbox、广告含 LinkedIn 营销） | 637.1 | 188.7 | 29.6% |

重述后的产品线（FY26，亿美元，同比）：**Azure 1,019.4（+40.4%）**｜M365 cloud（商业+消费）1,003.0（+18.6%）｜生产力与服务器许可 372.9（+5.4%）｜搜索与广告 248.4（+12.0%）｜Xbox 217.9（−7.1%）｜Industry solutions 203.5（+10.5%）｜Windows OEM 与设备 170.9（−1.3%）｜Frontier 与支持服务 82.6（+6.4%）。

**重述的商业模式含义（观点）**：微软第一次给出 Azure 的绝对收入序列（旧口径只说"超过 1,000 亿"）——这是透明度提升；但同时把 GitHub 云、Security Copilot 从 Azure 挪进 M365 commercial cloud，把 LinkedIn 拆散——**FY27 起"Azure 增速"和"M365 商业云增速"都比旧口径好看（重述后 FY26 M365 商业云 +18%/+15% CC，旧口径 +17%/+14%），而 LinkedIn 独立披露消失**。读 FY27 财报必须用重述基数。

**本维度结论：★4**。收入结构是"高利润率存量收租（PBP）+ 中利润率高增长算力（IC）+ 低利润率消费存量（MPC）"，三者中 PBP 决定当下利润，IC 决定未来增长、也决定 Capex 风险。

> 段永平："生意模式最重要的是能不能持续地赚钱，而不是这一年赚多少。"——PBP 能持续赚钱的证据充分；IC 能不能在 1,750 亿 Capex 之后持续赚钱，目前是"数据不足"。

## 3. 飞轮：分发与数据飞轮，AI 接入后是强化还是侵蚀

### 3.1 微软的飞轮结构

```
Windows 装机 → 企业协议（EA）/M365 席位 → Teams/SharePoint/Entra 身份 → 数据沉淀（Graph）
      ↓                                                             ↓
  GitHub（开发者）→ Azure（工作负载）←── 数据引力 ←── M365/Dynamics/LinkedIn 数据
```
飞轮的核心不是网络效应，而是**同一个销售动作可以卖越来越多的 SKU**（E3→E5→E7→Copilot→Azure 承诺）。

### 3.2 AI 接入后的证据（先摆数据）

| 指标 | 数据 | 来源与等级 |
|---|---|---|
| M365 Copilot 付费席位 | Q3 FY26 "超 2,000 万"；Q4 FY26 "超 3,000 万"，净新增席位环比翻倍以上 | 3,000 万：一手（8-K Ex.99.1 Nadella 引言）；2,000 万与环比：二级（Q3/Q4 电话会转录） |
| Copilot ARPU / 续费率 / 单独收入 | **未披露** | 10-K 只写"revenue per user growth driven by Microsoft 365 Copilot and Microsoft 365 E5" |
| M365 商业云收入 vs 席位 | FY26 收入 +17%，席位 +6% → 隐含每席位收入 **约 +10%**；FY25 收入 +15% | 一手（FY26/FY25 10-K） |
| Copilot 收入上限估算 | 3,000 万席 × $30/月标价 × 12 = **约 108 亿/年**（上限，实际含折扣与捆绑，估计），≈ M365 商业产品与云服务 1,020 亿的 10.6%、总收入 3.3% | 本报告估计（`financial_rigor.py calc`） |
| 渗透率 | 3,000 万 / 商业席位基数。公司 FY26 未披露基数；聚合博客引"4.5 亿" → 约 6.7%（**单一低级别来源**） | 估计 |
| 采用深度 | 5 万席以上客户数同比 7 倍以上；将 Copilot 部署到多数信息工作者的企业客户数环比 +75%；每用户对话数同比接近翻倍；周活跃度与 Outlook/Teams 相当 | 公司官方博客（2026-07-30，准一手，未审计） |
| GitHub Copilot | 6 月改为按用量计费后收入环比 +60%；企业版组织数约 14 万（Q3，同比近 3 倍）；"5,000 万用户" | 二级（电话会转录）；用户数为转录摘要，未见原文 |
| "AI 业务"年化收入 | Q3 FY26 "超 370 亿 ARR，+123%" | 二级（Q3 电话会转录）；**口径公司未在 SEC 文件定义** |
| Azure 增速中 AI 贡献点数 | **FY26 四个季度均未披露**（Q1 FY26 Hood 只说"Azure AI services revenue was generally in line with expectations"） | 二级；数据不足 |
| OpenAI 贡献收入 | FY26 来自 OpenAI 商业安排的收入（含收入分成）**241 亿**，占总收入 7.3%、Microsoft Cloud 11.2%、重述 Azure **23.6%（上限，因含收入分成）** | **一手：FY26 10-K Note 1（ASC 850 关联方披露）** |
| PBP 成本 | FY26 PBP 成本 +12%，10-K 原文："driven by investments in AI infrastructure to support Microsoft 365 Copilot seat and usage growth" | 一手 |

### 3.3 强化还是侵蚀（逻辑推导）

**强化的证据**：（1）Copilot 在两年半内做到 3,000 万付费席位，这只有靠 EA 分发才可能——飞轮的"分发"一环被 AI 验证；（2）M365 商业云每席位收入增速由 FY25 的约 +8%（估计）升到 FY26 约 +10%，方向与"Copilot 拉 ARPU"一致；（3）Azure 重述口径 FY26 +40%，且 FY27 Q1 指引 44-45% CC 加速。

**侵蚀/未证实的证据**：（1）Azure +43% 与 Synergy 口径的市场增速 +43% 相同，Azure 份额 20% 与一年前持平，Google 从 13% 升至 15%——**Azure 不是 AI 时代的份额获得者，只是跟随者**（行业机构口径）；（2）Microsoft Cloud 毛利率 FY25 69% → FY26 66%（一手，两份 10-K）→ Q4 FY26 65%（二级）：AI 收入在稀释云毛利率；（3）Copilot 的 ARPU、续费率、单独收入三项关键变现指标全部缺失——"席位数"是一个可以靠捆绑与折扣做大的指标（观点）；（4）OpenAI 一家占 Azure 收入上限 23.6%，飞轮里最大的一个齿轮不是微软自己的客户群，而是它的被投企业。

**本维度结论：★3**。分发飞轮被 AI 强化（证据充分），数据/利润飞轮是否被强化"数据不足"，毛利率数据倾向于"暂时侵蚀"。

> 段永平："差异化就是用户需要而别人没有的东西。"——Copilot 目前的差异化更多在"已经在你的 Word/Outlook/Teams 里"，而不是模型本身。这是分发优势，不是技术优势。

| **分发（Windows 装机 / EA）** | Copilot 3,000 万席位是分发力的直接证明；M365 商业云 1,020 亿收入建立在 EA 之上；FY27 起 GitHub 也并入这个销售口径 | Windows OEM 与设备 Q4 −7%（一手）、FY27 Q1 指引"低二十位数下滑"（重述文件）；分发帮不了 Bing（份额未变），说明分发只对"默认即够用"的产品有效 | **★5** |
| **技术壁垒（自研芯片 / 模型层）** | Maia 200 已在 US Central 部署，US West 3 跟进（公司新闻，2026-01）；持有 OpenAI 模型与产品 IP 权利至 2032（10-K + 官方博客）；Foundry 接入 Anthropic 模型 | Maia 200 只供内部、仅 1-2 个区域，对 NVIDIA 依赖度未量化；**2026-04 起 OpenAI IP 许可变为非独家，OpenAI 可在任何云上提供全部产品**（官方博客 2026-04-27）；微软自有前沿模型无公开证据；10-K 风险因素原文承认"Our AI strategy also depends in part on strategic relationships with third parties… In some cases, these parties are significant customers of Azure" | **★2** |

**护城河综合（观点）：★4**。微软的护城河是"绑定 + 分发"型，不是"技术"型。这在 AI 时代是双刃剑：绑定保证了 AI 产品的初始分发，但如果模型层被商品化、而微软又不掌握前沿模型，那么 Copilot 的溢价能力取决于捆绑，而捆绑正是监管盯着的地方。

## 5. 用户 / 企业客户 / 开发者 / 云客户：独特价值与可替代性

| 客户群 | 微软提供的独特价值 | 可替代性 | 证据 |

## 6. 业务矩阵：协同与拖累，以及 OpenAI 的结构性依赖

### 6.1 协同矩阵

| 组合 | 协同证据 | 拖累/风险 | ★ |
|---|---|---|---|

### 6.2 OpenAI 的结构性依赖（本报告最重要的发现之一）

**一手事实（FY26 10-K Note 1，ASC 850 关联方披露）**：
- 微软对 OpenAI 的投资按权益法核算，**"approximate 25% interest on an as-converted basis"**（底稿 §7 写 27%，来自 2025-10 博客；10-K 反映 FY26 内进一步稀释后的比例）
- FY26 **来自 OpenAI 商业安排的收入（含收入分成）241 亿**；6 月 30 日应收账款 60 亿（约 90 天收入，估计）
- 注资承诺 130 亿，已注资 119 亿；按 HLBV 法计算权益法损益；FY26 因 OpenAI 重组录得稀释收益

**推算 OpenAI 占 RPO 的比例（估计，公司未披露）**：
设 FY25 末商业 RPO = 6,780 / 1.84 = 3,685 亿（由 +84% 反推）。电话会称剔除 OpenAI 后 RPO +25%（二级）。令 FY25 末 OpenAI 占 RPO 为 X，则 FY26 末 OpenAI RPO = 6,780 − 1.25 × (3,685 − X) = 2,174 + 1.25X。
- X = 0（极端下限）→ OpenAI RPO ≈ 2,174 亿，占 **32%**
- X = 1,000 亿 → ≈ 3,424 亿，占 **50%**
- OpenAI 2025-10 承诺增量 2,500 亿（官方博客），与上述区间相容
**结论：OpenAI 占商业 RPO 大约三分之一到一半（估计），单一关联方客户。** RPO 加权久期 2.3 年、约 30% 在 12 个月内确认（一手，10-K Note 12）。

**依赖链条**：模型（IP 至 2032，但非独家）→ 收入（241 亿，7.3% 总收入，Azure 上限 23.6%）→ RPO（估计 32-50%）→ 非经营损益（FY26 +65 亿）→ Capex 决策（为 RPO 建产能）。**任何一环变化都会传导到其他环**。

**反面**：（1）2026-04 修订让 OpenAI 可以离开 Azure，但同时也让微软不再向 OpenAI 支付分成、并可独立追求 AGI（官方博客）——依赖是双向减弱的；（2）Azure 剔除 OpenAI 的增速公司未披露，"数据不足"；（3）微软已在 10-K 风险因素中明文提示这一依赖（一手），不属于隐藏风险。

**本维度结论：★3**。协同真实存在（M365×Copilot 最强），但 Xbox 是持续拖累，OpenAI 是"最大协同同时也是最大集中度"。

**反面**：（1）RPO 6,780 亿 × 30% ≈ 2,034 亿将在 12 个月内确认（一手）——Capex 对应的是已签合同，不是猜需求；（2）"需求持续超过供给"（二级，连续 6 个季度）；（3）折旧年限延长会让 FY27 报表利润率好看，但这不改变现金流——投资者应看 FCF 而非 EPS。

> 段永平："买股票就是买公司，买公司就是买其未来现金流的折现。"——微软眼下的问题不是"有没有现金流"，而是"未来现金流多大程度上已经被承诺出去"。

**本维度结论：★3**。四问中问二（FCF）给出否定答案，问四（能力圈）给出减分，问一、问三给出肯定答案。

### 8.2 "RPO 6,780 亿剔除 OpenAI 后 +25%"意味着什么

- +25% 仍高于 FY26 营收增速（+18%）与 Microsoft Cloud 增速（+27%）之间，说明**非 OpenAI 的企业需求是真实且加速的**——这是对"全靠 OpenAI"叙事的反证。
- 但 +84% → +25% 的落差意味着：市场看到的"RPO 翻倍"中，约 70% 的增量来自一个关联方客户（估计）；而这个客户在 2026-04 后获得了多云自由。
- RPO 是"合同"不是"现金"：应收 60 亿 vs 241 亿收入，回款正常；但 RPO 剩余 70% 在 12 个月之后确认，其兑现取决于 OpenAI 自身融资能力（本报告未核 OpenAI 财务，数据不足）。

## 9. 本维度总体结论

| 维度 | ★ |
|---|---|
| 商业模式本质与收入结构 | ★4 |
| 飞轮与 AI 接入 | ★3 |
| 护城河综合 | ★4 |

| 段永平四问 + Capex | ★3 |
| **商业模式综合** | **★4** |

**综合判断（观点，基于以上数据）**：微软是一门"存量极好、增量存疑"的生意。存量（PBP，60% 利润率、73% 增量利润率、席位与许可仍在增长）是全球最好的收租生意之一，★5 级别；增量（Azure/AI）目前表现为"跟随市场的增速 + 下降的毛利率 + 一个占 RPO 三分之一到一半的关联方客户 + 45% 营收的 Capex"，★2-3 级别。两者合在一起给 ★4，而不是市场共识隐含的 ★5。

**什么证据会让本报告上调至 ★5**：Copilot ARPU 与续费率被披露且向好；Microsoft Cloud 毛利率止跌；OpenAI 占 Azure 比例下降的同时 Azure 增速不降；FY27 FCF ≥ 400 亿。
**什么证据会让本报告下调至 ★3**：席位披露停止；云毛利率 < 62%；OpenAI 关联收入占比上升；FY27 FCF < 250 亿。

> 段永平："做对的事情，把事情做对。"——微软把"事情做对"（执行、分发、销售）的能力毋庸置疑；1,750 亿 Capex 是不是"对的事情"，要到 FY28 才知道。本报告不预设答案。
